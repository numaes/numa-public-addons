# Numa Web Relative Dates

**Odoo 20.0** | LGPL-3 | NUMA Extreme Systems

**Status: migrated to Odoo 20.0** (module version `20.0.1.0.0`). The template it hangs
off was renamed, and what Odoo ships around it changed enough to be worth reading before
deciding to keep the module: see [Migration to Odoo 20.0](#5-migration-to-odoo-200).

Marks the **relative** date filter so that a user can tell it is counted from today.

---

## 1. What it is for

A date filter saved as a favourite is normally frozen: the concrete date is stored, and a
week later the filter is useless. Odoo can do better — a relative filter produces a domain
made of expressions that are re-evaluated on every use — but the editor does not say what
the range is counted from, or that saving it as a favourite keeps it moving.

This module adds that information where the user is looking: a `from today` label next to
the amount and unit selectors, with a tooltip saying that the filter is recalculated and
that saving it as a favourite does not freeze it.

**It changes no behaviour and no data.** It is a label. Removing the module breaks no
saved filter, because the filters are generated by core.

---

## 2. Installation

Depends only on `web`. No models, no views, no data: a single assets XML.

---

## 3. How the filter is used

See [`docs/relative_date_filters.md`](docs/relative_date_filters.md) — the step by step,
what gets stored and why it works, and the limits of the native implementation.

---

## 4. What this module does NOT do

It does not add units or operators. Widening what the relative editor offers means forking
core conversion logic, and this module is a label.

## 5. Migration to Odoo 20.0

### 5.1 The anchor moved

Up to 18.0 the free-form relative editor was the `within` operator and its template was
`web.TreeEditor.Within`. Odoo 20 replaced it with the `is in range` operator plus a value
type, and the editor is now `web.TreeEditor.relativeRange`
(`tree_editor_components.js:60`). The old template does not exist any more.

That kind of break is silent: `generate_xml_bundle` raises nothing when the parent of a
template extension is missing, it only appends a `console.error(...)` to the bundle. The
hint would simply have stopped appearing. The test suite asserts the anchor against the
generated bundle precisely for this.

### 5.2 Core now ships named relative presets

Odoo 20 added ready-made entries to the value list — *Last month*, *Year to date*, *Last
365 days*, and others. They are generated as smart dates (`today`, `today -1m`), so they
are relative too, and their names say so.

### 5.3 The free-form relative range is debug-only

`["relativeRange", _t("Relative range"), { debugOnly: true }]`
(`tree_editor_components.js:106`). A user not in developer mode never sees the editor this
module annotates.

**Taken together, 5.2 and 5.3 mean the module reaches far fewer users than it did in
18.0.** What it adds is still not said by core — the presets do not state that a saved
favourite is recalculated — but the discoverability problem the module was written for is
largely solved upstream. It is migrated and green; whether it is still worth installing is
a decision for whoever runs it.

## 6. Tests

```bash
odoo-bin -d <database> -i numa_web_relative_dates --without-demo \
         --test-enable --test-tags=/numa_web_relative_dates --stop-after-init
```

Five tests, all against the **generated bundle** rather than the source file: that the core
template still exists under that name, that our extension is registered against it, that
the bundle does not report the parent as missing, that the text and the tooltip arrive, and
that the text stays flush against its tags so the `.po` msgid keeps matching.
